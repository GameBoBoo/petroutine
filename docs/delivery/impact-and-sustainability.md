# ผลกระทบ ต้นทุน และการดำเนินงานต่อ

## สมมติฐานผลลัพธ์

Shared Today และประวัติผู้ทำอาจช่วยลดการลืม/ดูแลซ้ำ ยังไม่มีข้อมูลทดลองจริง ห้ามใช้ข้อความว่า “ลดได้ X%” หรือ “ทำให้สัตว์สุขภาพดีขึ้นแล้ว”

แผนเก็บข้อมูลที่เสนอ: 7 วันใช้วิธีเดิมเป็น baseline จากนั้น 7 วันทดลอง PawRoutine กับครัวเรือนเดิม จดงานที่ควรทำและการเปลี่ยนตารางให้ครบ ระยะเวลาและจำนวนครัวเรือนเป็นข้อเสนอ ต้องยืนยันความพร้อมก่อนเริ่ม ไม่ใช่ผลที่เก็บแล้ว

| ตัวชี้วัด | นิยาม | วิธีเก็บ | baseline/เป้าหมาย |
|---|---|---|---|
| อัตรางานที่ลืม | งานที่ควรทำแต่ไม่ได้ทำ ÷ งานที่ถึงกำหนด | diary + ถามยืนยัน ไม่ถือว่าทุก overdue คือการลืม | ยังไม่วัด/เสนอเป้าหมายให้ลดลงจาก baseline |
| งานซ้ำโดยไม่ตั้งใจ | เหตุการณ์ซ้ำที่ผู้ดูแลยืนยัน | diary + สัมภาษณ์ | ยังไม่วัด |
| เวลาตรวจว่าใครทำแล้ว | วินาทีจากเริ่มค้นจนตอบถูก | งานทดสอบเดียวกันก่อน/หลัง | ยังไม่วัด |
| ความเข้าใจ Alert | อธิบายได้ว่าไม่ใช่คำวินิจฉัย | teach-back หลังทดลอง | ยังไม่วัด; หากเข้าใจผิดต้องแก้ข้อความ |

จำนวนบันทึก/ผู้ลงทะเบียนเป็น output ไม่ใช่หลักฐานผลต่อสุขภาพสัตว์ วิเคราะห์ผลแบบ paired ในครัวเรือนเดิม ระบุ missing data, learning effect และ self-report bias

## ผู้รับประโยชน์และต้นทุน

Primary user คือผู้ดูแลในบ้าน Secondary user คือผู้ดูแลร่วมและผู้ที่รับรายงานไปคุยกับสัตวแพทย์ ระบบไม่ให้สัตวแพทย์เข้าถึงข้อมูลจริงอัตโนมัติ

รุ่น Mini Project ยังไม่มีรูปแบบรายได้ที่พิสูจน์แล้ว สมมติฐานคือทีม/สถาบันสนับสนุนค่า hosting สำหรับ pilot ไม่อ้างว่ามีลูกค้าจ่ายเงินหรือ partnership

| รายการงบ | สูตรที่ต้องกรอกด้วยใบเสนอราคาจริง |
|---|---|
| Compute/DB | ค่าเครื่องต่อเดือน + storage + snapshot |
| AI | input tokens/1M × ราคา input + output tokens/1M × ราคา output |
| Backup | GB ที่เก็บ × ราคา/GB + egress/restore |
| ดูแลระบบ | ชั่วโมง support/maintenance × ต้นทุนต่อชั่วโมง |
| รวม | fixed cost + variable cost; หาร active households เพื่อประมาณต้นทุนต่อบ้าน |

ยังไม่มีตัวเลขราคาที่ตรวจยืนยัน ใช้โควตา AI, monitoring usage และปิด AI ได้เพื่อลดการพึ่ง vendor การเปลี่ยน provider ต้องทดสอบ schema/quality/privacy ใหม่

## ข้อได้เปรียบและความเสี่ยง

จุดต่างที่มีในผลิตภัณฑ์คือ shared care, audit/Undo, baseline ที่ย้อน source ได้ และรายงานจากข้อมูลของบ้าน แต่ยังไม่มีหลักฐานว่าเป็น unfair advantage ที่คู่แข่งเลียนแบบยาก การสะสมความรู้จาก pilot และความสัมพันธ์ผู้เชี่ยวชาญเป็นแนวทางในอนาคต ไม่ใช่ทรัพย์สินที่มีแล้ว

ความเสี่ยง: เข้าใจ Alert เป็น diagnosis, กรอกข้อมูลผิด, ข้อมูลไม่ครบ, ข้อมูลบ้านรั่ว, AI ตอบช้า/ผิด และ vendor cost แนวรับมือคือ disclaimer/source, edit+audit, missing-data state, authorization, consent/timeout และ quota พร้อมตรวจผู้ใช้จริงว่าเข้าใจตรงกัน
