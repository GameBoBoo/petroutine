# การตรวจปัญหาและทดลองกับผู้ใช้จริง

สถานะ: **ยังไม่มีผลวิจัยจริงใน repository** เอกสารนี้เป็น protocol และแบบบันทึก ไม่ใช่ผลสัมภาษณ์

มี [บทสัมภาษณ์จำลอง 4 บทบาท](interview-rehearsal.md) สำหรับซ้อมคำถามและสถานการณ์ โดย วศิน จันทร์ก้อน รับผิดชอบการเก็บข้อมูลจริงตามแผนทีม

## กลุ่มและความยินยอม

รับผู้ดูแลสุนัขหรือแมว 5–8 คนตามแผนเดิม โดยอย่างน้อย 3 คนมีผู้ดูแลร่วม ขออนุญาตก่อนจด/บันทึกเสียง ให้ถอนตัวได้ ใช้ P01… แทนชื่อ ไม่ใส่ข้อมูลสุขภาพหรือข้อมูลติดต่อจริงใน Git/Demo

## ขั้นตอน

1. สัมภาษณ์ 10–15 นาทีด้วยคำถามใน `../user-research.md` ขอเหตุการณ์ล่าสุดที่ลืม/ทำซ้ำ วิธีเดิม และผลกระทบ แยกข้อเท็จจริงจากความเห็น
2. ให้ทดลองด้วยข้อมูลสมมติ: เข้าร่วมบ้าน → สร้างกิจวัตร → ทำงานเสร็จ → ดูประวัติ → เช็กอิน → หา source ของ Alert
3. จดสำเร็จเอง/ต้องช่วย/ทำไม่สำเร็จ เวลา ปัญหา และคำอธิบายของผู้ใช้ ไม่ชี้นำก่อนเริ่ม
4. ถามว่าข้อมูลใดเข้าใจผิด คำว่า baseline/alert ทำให้คิดว่าเป็นการวินิจฉัยหรือไม่ และจะใช้ต่อเพราะอะไร
5. สรุป themes, จำนวนคนที่พบแต่ละปัญหา ข้อจำกัด sample และ corrective action ที่โยงไป Issue/AC

## แบบบันทึกที่ยังว่าง

| รหัส | วันที่/วิธีเก็บ | บริบทผู้ดูแล | เหตุการณ์ปัญหาจริง | งานทดลอง/ผล | ข้อสังเกต/ยินยอม |
|---|---|---|---|---|---|
| ยังไม่มีข้อมูล | — | — | — | — | ต้องเก็บจริง |

คัดลอก `research-responses.csv` ไปโฟลเดอร์ส่วนตัว เช่น `artifacts/research/` ก่อนกรอกข้อมูลจริง เก็บ template ใน Git ให้ว่างและเผยแพร่เฉพาะบทสรุปที่ปกปิดตัวตน อย่าแทนช่องว่างด้วยคำตอบที่ AI สร้าง สถิติ/งานวิจัยภายนอกที่เพิ่มต้องระบุ URL ปี วิธีเก็บและข้อจำกัด

## เกณฑ์สรุปผล

รายงานจำนวนคนที่ทำงานสำเร็จและรายละเอียด failure แยกตามงาน ห้ามสรุปว่าใช้ได้กับประชากรทั้งหมดจาก sample เล็ก ความต้องการเพิ่มฟีเจอร์เป็นข้อมูลเสนอแนะ ไม่เปลี่ยนขอบเขตอัตโนมัติ
