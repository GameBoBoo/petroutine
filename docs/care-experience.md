# Care experience update

อัปเดต 23 ตุลาคม 2026: สถานะ UI ล่าสุดตามรายการด้านล่างใช้แทนรายการฟีเจอร์รอบแรกที่ระบุไว้ในส่วนประวัติ

## UI ปัจจุบัน

- หน้ากิจวัตรใช้แถวกระชับ: ชื่อ/สัตว์/ประเภท เวลา/วันทำซ้ำ ผู้รับผิดชอบ และแก้ไข/ลบ พับรายละเอียดเสริม มีค้นหา/กรองสัตว์ และหน้าหลักแบ่งครั้งละ 10 รายการ แท็บรายสัตว์ใช้แถวชุดเดียวกันแต่ไม่มี pagination
- เปลี่ยน “เก็บข้อมูลเก่า” เป็น “ลบ” ในข้อมูลสุขภาพ Passport เช็กอิน และข้อความประวัติ Backend ยังคง soft archive และรักษา care history
- ก่อนลบมี popup ยืนยัน ลบบ้านต้องพิมพ์ชื่อ ส่วนการบันทึกฟอร์มและสถานะสำคัญใช้ `ConfirmationProvider` รวม Complete/Skip/Reopen/Undo, เลื่อนเวลา/มอบหมาย, สุขภาพ/ติดตาม, สมาชิก และ Settings/AI consent ยกเลิกแล้วไม่ส่ง mutation
- Dropdown ใช้ `SelectField` กับตัวเลือกกลาง คำอธิบายสั้น สัตว์/สมาชิกตามบ้าน และอีเมลแยกคนชื่อซ้ำ ผู้รับผิดชอบอยู่ในฟอร์มกิจวัตรหลัก ดู [Popup fields](popup-fields.md)
- จัด SearchField, ช่องหมายเหตุ, ตัวเลือกงาน, การแก้การกดผิด และภาพรวมสัตว์ให้อ่านง่าย popup ซ่อน scrollbar และแสดงเมื่อ hover
- นำส่วนเริ่มดูแลไปด้วยกัน, Recovery Tools, รูปและข้อมูลติดต่อ, ลิงก์แม่แบบ Quick Add และ pause toggle/ตัวกรองพักกิจวัตรออกจาก UI; API/ข้อมูลเดิมยังคงอยู่
- Owner เปลี่ยนรหัสเชิญอายุ 7 วัน นำสมาชิกออก และโอนเจ้าของได้แล้ว Migration 016 รองรับข้อมูลรอบ care experience

## หลักฐานล่าสุด

ก่อนเพิ่ม confirmation รอบล่าสุด E2E 12 ผ่าน/2 ข้าม และ targeted care screens desktop/mobile 2 ผ่าน หลังเพิ่ม confirmation และแถวกิจวัตร production Docker build/deploy ผ่าน health `ok/ok` ยังไม่ได้รัน unit/API/E2E ใหม่กับ flow ยืนยัน

ปรับตามคำขอล่าสุด: นำส่วนเริ่มดูแลไปด้วยกันและส่วนกู้คืนออกจากทุกหน้าจอ เปลี่ยน dropdown ใหม่เป็น SelectField ของระบบ และจัดหน้าจอสมาชิก โปรไฟล์ ปฏิทิน และตัวเลือกกราฟใหม่

ขอบเขตตามคำขอ: เริ่มใช้งาน บ้าน/สมาชิก โปรไฟล์ Today การแก้งาน ผู้รับผิดชอบ Quick Add ปฏิทิน Baseline Alerts Dashboard Shared Monitoring Timeline/ประวัติ Vet Report กู้คืน และ Settings

## ประวัติสิ่งที่เพิ่มรอบแรก (บาง UI ถูกนำออกภายหลัง)

- คำแนะนำเริ่มต้น 4 ขั้นจากข้อมูลบ้าน สัตว์ กิจวัตร และงานที่ทำแล้ว
- Owner เปลี่ยนรหัสเชิญ (อายุ 7 วัน) นำสมาชิกออก และโอนเจ้าของบ้าน พร้อมหน้าทบทวนก่อนยืนยัน
- เมื่อนำสมาชิกออก งานและการติดตามของสมาชิกกลับเป็นงานส่วนกลาง ประวัติไม่ถูกลบ
- รูปสัตว์ PNG/JPEG/WebP ไม่เกิน 1 MB และข้อมูลติดต่อฉุกเฉิน รูปเก็บเป็น data URL ใน PostgreSQL เฉพาะโปรไฟล์สัตว์
- Today แสดงผู้รับผิดชอบ ผู้บันทึก สรุปสถานะ เวลาอัปเดต รีเฟรชเมื่อกลับเข้าหน้า และทุก 60 วินาทีเมื่อหน้าเปิดอยู่
- เปิดงานที่ complete/skip ผิดกลับเป็น pending พร้อมเหตุผล ตรวจสิทธิ์ผู้บันทึกหรือ Owner และ mutation version การแก้ไขมี Activity เดิมและใหม่
- เปลี่ยนผู้รับผิดชอบด้วยการยืนยัน และปุ่มรับงานเองเฉพาะครั้ง
- Quick Add จำสัตว์และชนิดบันทึกล่าสุดแยกบ้าน โดยไม่จำค่าข้อมูลสุขภาพ
- ปฏิทินกรองสัตว์/ประเภท เปิดพื้นที่ข้อมูลสัตว์จากชื่อรายการ และเลื่อนเวลา/เปลี่ยนผู้รับผิดชอบเฉพาะครั้ง รวมงานอนาคตที่ยังไม่สร้าง occurrence
- Baseline แสดงสิ่งที่ต้องบันทึกต่อ พร้อมวันที่ต้นทาง; ไม่เปลี่ยนกฎคำนวณเดิม
- Alerts เปิดบันทึกติดตามเพิ่มเติมและบันทึกว่าติดตามแล้วพร้อมผลที่สังเกตได้จากหน้ารายการได้
- Dashboard เลือกหัวข้อกราฟและอธิบายวันที่ขาดข้อมูล
- Timeline ค้นชื่อ/หมายเหตุ/ผู้บันทึกในฐานข้อมูลก่อนแบ่งหน้า ประวัติงานค้นในผลลัพธ์ช่วงที่โหลดอยู่
- Vet Report เลือกหัวข้อก่อนดาวน์โหลด PDF และแสดงจำนวนวันที่มีเช็กอิน
- Owner กู้คืนบ้าน สัตว์ กิจวัตร การดูแล สุขภาพ Passport และเช็กอินผ่าน UI; ต้องกู้สัตว์ก่อนรายการลูก
- Settings เชื่อมความยินยอม AI และการกู้คืนข้อมูล

## AI ที่ตกลงใช้

AI ถามค้น/สรุปข้อมูลที่มีอยู่พร้อม source และสิทธิ์รายบ้าน โค้ดปัจจุบันเพิ่ม care draft จากข้อความ โดยไม่บันทึกเอง ผู้ใช้ต้องตรวจและยืนยันผ่าน API ปกติ ผลตรวจแยกอยู่ใน delivery/course-results.md

เพิ่มคำถามสรุปสำเร็จรูป จัดลำดับข้อมูลตามหัวข้อคำถามและเวลา และแจ้งเมื่อใช้บริบทเพียงบางส่วน ขีดจำกัดเดิม 240 facts ยังใช้ การค้นเป็นกฎคำสำคัญ ไม่ใช่ semantic search และไม่รับประกันว่ารายการทุกชนิดในช่วงยาวจะถูกส่งครบ

## การใช้ schema

เพิ่ม migration 016 แบบ additive และรันซ้ำได้ รหัสเชิญเดิมได้อายุ 7 วันนับจากการเพิ่มคอลัมน์ครั้งแรก; การรันซ้ำไม่ต่ออายุรหัสเดิม

โค้ดชุดใหม่ต้องใช้ schema 016 ก่อนเริ่ม server โดย Docker image รัน migrations ตอน start ตามปกติ
