# แผนพัฒนา Phase 11 — AI ช่วยอธิบายข้อมูล (Optional)

สถานะ: Implementation ของ Daily Summary และ Wellness Questions พร้อมสวิตช์เจ้าของบ้านแล้ว (20 ต.ค. 2026); ตรวจ Provider จริงด้วยข้อมูลสังเคราะห์ผ่าน `npm run ai:check`, Unit/API 68/68 และ AI E2E desktop/mobile 2/2 ผ่าน ยังต้องปรับ E2E เดิม 6 เคสที่อ้าง UI รุ่นก่อนและประเมินคุณภาพคำตอบก่อนอ้าง release gate เต็มรูปแบบ

## เป้าหมาย

เพิ่มผู้ช่วยแบบอ่านอย่างเดียวที่เป็นตัวเลือก ให้สมาชิกเข้าใจบันทึกการดูแลและข้อมูลสุขภาวะที่มีอยู่ คำตอบทุกข้ออ้างอิงข้อมูลที่ PawRoutine เตรียมให้ แสดงช่วงวันที่และรายการต้นทาง และยังใช้งานต่อได้เมื่อ AI ใช้ไม่ได้

ฟีเจอร์ Phase 5–10 ต้องทำงานได้เหมือนเดิมเมื่อปิด AI ระยะนี้ต้องไม่ทำให้ PawRoutine กลายเป็นระบบวินิจฉัยหรือแนะนำการรักษา

## ขอบเขตรุ่นแรก

1. **สรุปการดูแลประจำวัน:** สรุปงานดูแลและเช็กอินของสัตว์หนึ่งตัวในวันเดียวตามเวลา Bangkok พร้อมลิงก์ไปยังบันทึกต้นทางของแต่ละข้อเท็จจริง
2. **ถามข้อมูลสุขภาวะ:** ตอบคำถามที่จำกัดขอบเขตเกี่ยวกับแนวโน้ม โดยใช้สัตว์ ช่วงวันที่ baseline และ Alert ที่ระบบมีอยู่แล้ว แอปเป็นผู้คำนวณตัวเลข ส่วนโมเดลมีหน้าที่อธิบายข้อมูลที่ได้รับเท่านั้น
3. **ควบคุมการเปิดใช้:** ปิด AI ไว้เป็นค่าเริ่มต้น ให้ Owner ที่ได้รับอนุญาตเปิดใช้ได้ และปิดได้โดยไม่สูญเสียสิทธิ์ใช้รายงาน Dashboard หรือแบบฟอร์มปกติ

เลื่อนการแปลงข้อความธรรมชาติเป็น Care Log ออกจากรุ่นแรก เพราะเป็นทางเขียนข้อมูลและข้อความกำกวมอาจสร้างประวัติการดูแลหรือข้อมูลยาไม่ถูกต้อง หากพิจารณาภายหลัง ต้องสร้างเป็นร่างที่แก้ไขได้และให้ผู้ใช้ยืนยันก่อนบันทึกทุกครั้ง

## นอกขอบเขต

- วินิจฉัย คัดกรอง/จัดระดับความเร่งด่วน แนะนำการรักษา คำนวณขนาดยา เปลี่ยนยา หรือแนะนำให้หยุดยา
- สร้างค่าตรวจวัด baseline หรือ Alert ขึ้นเอง หรือแก้ข้อมูลต้นทาง
- ใช้บริบทข้ามสัตว์/ข้ามบ้าน, เก็บประวัติสนทนาแบบไม่จำกัด, อัปโหลดไฟล์/รูป, ส่ง push/email หรือสร้างรายการอัตโนมัติ
- เลือก AI Provider ก่อนตรวจสอบความเป็นส่วนตัว การจัดการข้อมูล ค่าใช้จ่าย และข้อจำกัดสภาพแวดล้อมที่จะ deploy

## ลำดับการส่งมอบ

### 0. ตรวจความพร้อมและกำหนดเงื่อนไข

- ยืนยันว่า Wellness, Alert, Dashboard, Report และ permission isolation ปัจจุบันยังผ่านชุดทดสอบ โดยถือการทำงานปัจจุบันเป็น fallback
- เพิ่ม E2E smoke สำหรับดาวน์โหลด Vet Report โดยตรงก่อนแก้ส่วนรายงานที่ใช้ร่วมกัน
- ตัดสินใจ Provider เงื่อนไขเก็บข้อมูล และสภาพแวดล้อมที่จะเปิดใช้ ห้ามส่ง provider secret ไปไว้ใน browser

### 1. ขอบเขตการเรียก AI ฝั่ง Server

- เพิ่ม adapter ที่ไม่ผูกกับ Provider รายเดียว อยู่หลัง feature flag/configuration และปิดไว้โดยค่าเริ่มต้น
- สร้าง context service ที่ตรวจสิทธิ์สมาชิกและสถานะ archive ทุกครั้ง รับเฉพาะ pet ID, intent ที่รองรับ และช่วงวันที่ Bangkok ที่จำกัด
- ส่งเฉพาะข้อมูลที่จำเป็น ตัด account ID, รายชื่อสมาชิกบ้าน, หมายเหตุที่ไม่เกี่ยวข้อง, credentials และข้อมูลสัตว์ตัวอื่นออก
- กำหนดคำสั่งถาวรให้โมเดลใช้เฉพาะข้อเท็จจริงที่ส่งให้ ระบุเมื่อหลักฐานไม่พอ และห้ามวินิจฉัยหรือแนะนำให้เปลี่ยนยา
- จำกัดขนาดคำขอ/คำตอบ, timeout, จำนวน retry และอัตราการเรียกต่อผู้ใช้ ห้ามบันทึก prompt หรือ health payload เต็มลง log ตามค่าเริ่มต้น ให้เก็บเพียง request ID, ผู้เรียก, สัตว์, ช่วงวันที่, Provider/model, เวลา, สถานะ และ source IDs

### 2. สรุปการดูแลประจำวัน

- เริ่มจากสรุป care entries ที่เกิดขึ้น งานที่ทำ/ข้าม และ Wellness logs ของสัตว์ตัวเดียวในวันที่เลือก
- บังคับรูปแบบคำตอบด้วย schema; ทุกข้อเท็จจริงต้องอ้าง source ID จาก context ที่ระบบเตรียมไว้
- แสดงป้ายว่า AI สร้าง วันที่ ลิงก์กลับบันทึกต้นทาง และข้อความสั้นว่าไม่ใช่คำวินิจฉัย
- หากสร้างไม่สำเร็จ ให้แสดง Timeline/Check-in ปกติและปุ่มลองอีกครั้ง ห้ามขวางการใช้งานฟอร์ม

### 3. คำถามสุขภาวะ

- รองรับชุดคำถามที่กำหนดขอบเขต เช่น “ช่วงนี้การกินเปลี่ยนไปอย่างไร” แทนช่องสนทนาอิสระ
- ให้แอปเตรียมค่าที่คำนวณ แนวโน้ม สถานะ baseline วันที่ขาด และ Alert ที่ยังทำงาน/คลี่คลายแล้ว จากนั้นส่งผลพร้อม source IDs ให้โมเดลอธิบาย
- schema คำตอบต้องมีข้อความ ช่วงวันที่ หลักฐานอ้างอิง และสถานะข้อมูลไม่เพียงพอ
- ปฏิเสธคำตอบที่อ้าง source ID นอก context หรือกล่าวอ้างเกินหลักฐาน โดย Dashboard และ Report ยังคงเป็นหน้าดูข้อมูลหลัก

### 4. ความเป็นส่วนตัว ความปลอดภัย และ rollout

- ตรวจการประมวลผลและการเก็บข้อมูลของ Provider ก่อนเปิดให้ใช้กับข้อมูลบ้านจริง
- เพิ่มการเปิด/ปิดอย่างชัดเจน และติดป้ายเนื้อหาที่ AI สร้างทุกครั้ง
- rollout หลัง feature flag โดยเก็บเฉพาะ operational metadata และ error ที่ลดข้อมูลส่วนบุคคลแล้ว
- ปิดใช้งานได้ทันทีด้วย flag; ฟีเจอร์หลักไม่ต้องพึ่ง migration หรือความพร้อมของ Provider

## เงื่อนไขข้อมูลและ API

- ทุก AI endpoint ต้องยืนยันตัวตนและใช้กฎ household membership/archive เดียวกับ API ข้อมูลต้นทาง
- รุ่นแรกไม่เก็บบทสนทนาถาวร หากมีความต้องการภายหลัง ต้องกำหนดอายุการเก็บ การลบ การ export สิทธิ์เข้าถึง และ audit ก่อน
- ห้ามบันทึกคำสรุปของ AI เป็น care/health record หากภายหลังต้องการเก็บ ต้องเป็นข้อมูลที่ผู้ใช้ยืนยัน มีป้าย provenance และ source references ชัดเจน
- เรียก Provider จาก Server เท่านั้น ห้ามมี secret key หรือ Provider SDK ใน client bundle

## แผนทดสอบและเกณฑ์ผ่าน

### Unit และ Contract

- context builder เลือกเฉพาะสัตว์ที่ระบุและบ้านที่มีสิทธิ์ พร้อมจำกัดช่วงวันที่
- schema validator ปฏิเสธหลักฐานหาย, source ID ที่ไม่รู้จัก, output ใหญ่เกิน และ response ที่ผิดรูปแบบ
- ข้อความในหมายเหตุที่พยายามสั่งโมเดลให้ละเมิดกฎ ต้องถูกมองเป็นข้อมูลไม่เชื่อถือและไม่สามารถสั่งให้เขียนข้อมูลได้
- timeout, Provider error, rate limit และ flag ปิด ต้องคืน fallback ที่ปลอดภัยและคาดเดาได้

### API และความปลอดภัย

- ผู้ไม่ login, คนนอกบ้าน, บ้านที่ archive และคำขอข้ามสัตว์ต้องอ่าน context/คำตอบไม่ได้
- AI endpoint เป็น read-only และเปลี่ยน care, wellness, baseline, alert หรือ report ไม่ได้
- log มีเฉพาะ metadata เชิงระบบ ไม่เก็บข้อความ prompt/context ที่อ่อนไหว

### E2E

- เมื่อปิด AI ฟีเจอร์เดิมและดาวน์โหลด Vet Report ยังทำงานได้
- เมื่อใช้ stub Provider สรุปรายวันต้องแสดง source links และวัน Bangkok ที่ถูกต้อง
- คำตอบ Wellness อ้างเฉพาะรายการที่ส่งให้และแสดงช่วงวันที่
- Provider ล้มเหลวแล้วฟอร์มปกติและ Rule-based Wellness ยังใช้ได้
- Owner เปิด/ปิดได้ และเนื้อหาที่สร้างแสดงป้าย AI บน desktop/mobile

### Release Gate

ต้องผ่าน Unit/API, production build, E2E desktop/mobile, privacy review, accessibility review และทดสอบ rollback ก่อนเปิดให้ผู้ใช้จริง Provider ต้องยังเป็นตัวเลือกและปิดเป็นค่าเริ่มต้นจนกว่าผู้ใช้เลือกเปิด

## เรื่องที่ต้องตัดสินใจก่อนเริ่ม

1. Provider และสภาพแวดล้อมใดเหมาะสมหลังตรวจความเป็นส่วนตัวและค่าใช้จ่าย?
2. ให้ Owner เปิดใช้ระดับบ้าน, ให้ deployment ควบคุม หรือใช้ทั้งสองชั้น? ค่าเริ่มต้นต้องปิด
3. บันทึกใดควรอยู่ในสรุปรุ่นแรก และควรจำกัดช่วงวันที่ถาม Wellness ไว้เท่าใด?

## นิยามการเสร็จ

ถือว่า Phase 11 เสร็จเมื่อ Summary และ Wellness Q&A แบบจำกัดขอบเขตผ่าน release gate, หลักฐานชี้กลับไปยังข้อมูลที่ผู้ใช้มีสิทธิ์อ่านได้, การปิด AI/Provider failure ยังรักษาฟีเจอร์เดิมครบ และอัปเดตสถานะกับ memory แล้ว Natural-language Care Log ต้องเป็นข้อเสนอแยกในอนาคต
