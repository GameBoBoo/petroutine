# PawRoutine — รายงานประกอบส่ง Mini Project

วันที่จัดชุด: 28 ตุลาคม 2026 · ชื่อบนผลิตภัณฑ์: PetRoutine · ชื่อ repository: PawRoutine

เอกสารนี้แยกผลระบบที่ตรวจแล้ว หลักฐานงานวิจัยภายนอก ประมาณการ และบทจำลอง ทุกคำกล่าวอ้างต้องอ่านตามประเภทหลักฐานนั้น ไม่มีการนำบทสัมภาษณ์จำลองมาแทนผลจากคนจริง

## 1. Problem Statement

โจทย์คือความไม่ชัดเจนของสถานะงานเมื่อข้อมูลดูแลสัตว์กระจายในความจำ แชต หรือกระดาษ ผู้ดูแลต้องตรวจให้ได้ว่าใครทำอะไร เมื่อไร และมีสิ่งใดเปลี่ยนไป สมมติฐานคือการรวมสถานะและประวัติอาจช่วยประสานงาน ส่วนความชุกและผลการลดงานลืมในผู้ใช้ PawRoutine ยังไม่ได้วัด

ใช้ [งานวิจัยภายนอกพร้อมข้อจำกัด](problem-evidence.md) เป็นฐานปัญหา งาน Odom et al. (2024) ศึกษา noncompliance ในกลุ่มคลินิกนิวซีแลนด์ ซึ่งมีหลายสาเหตุ จึงไม่นำตัวเลขนั้นมาใช้เป็นอัตราการลืมของครอบครัวไทย อีกแหล่งรายงานว่าครัวเรือนหลายคนอาจลืมน้อยลง จึงตั้ง root cause ที่ความชัดเจนของข้อมูล แทนการเหมารวมว่าจำนวนผู้ดูแลเป็นปัญหา

## 2. Solution และขอบเขต

Shared Today/Calendar แสดงงานและผู้รับผิดชอบ การยืนยันก่อน mutation, version/idempotency และ Undo รองรับการแก้ผิด Activity/Timeline เก็บประวัติ Wellness ใช้บันทึกรายวัน baseline/กฎการเปลี่ยนแปลงและ source links ส่วน Vet Report รวมข้อเท็จจริงไปประกอบการคุยกับสัตวแพทย์

AI เป็น optional สำหรับอ่าน/สรุปและเตรียม draft ผู้ใช้ต้องยินยอมและตรวจ draft ก่อนบันทึก ไม่อ้างความสามารถวินิจฉัยหรือปรับยา การทำงานหลักใช้ได้เมื่อปิด AI ดู [Requirements](../requirements.md), [AC](../acceptance-criteria.md) และ [Traceability](traceability.md)

## 3. Target Users / Target Market

ผู้ใช้หลักคือเจ้าของสุนัขหรือแมวที่ต้องการติดตามกิจวัตร ผู้ใช้ร่วมคือสมาชิกบ้านที่ช่วยดูแล Owner จัดการสมาชิกและตารางหลัก สมาชิกทำงานรายครั้งและดูข้อมูลเฉพาะบ้านที่มีสิทธิ์ ผู้รับรายงานใช้ข้อมูลที่ผู้ดูแลเลือกส่งต่อ ไม่มีระบบบัญชีคลินิกหรือ partnership ที่ยืนยันแล้ว

ขอบเขตการประเมินงบเริ่มที่ 10 ครัวเรือนเป็นสมมติฐาน pilot ไม่ใช่จำนวนลูกค้าที่มีแล้ว ช่องทางที่เสนอคือครอบครัวผู้ดูแลร่วมและเครือข่ายมหาวิทยาลัย โดยต้องรับสมัครและขอความยินยอมก่อนใช้ข้อมูลจริง

## 4. Social Impact & Assessment

Output ที่ยืนยันได้คือระบบและการทดสอบด้วยข้อมูล synthetic Outcome ที่ต้องศึกษาคือการลืม/ทำซ้ำโดยไม่ตั้งใจ เวลาค้นประวัติ และความเข้าใจ Alert ยังไม่อ้างว่าระบบลดเหตุการณ์เหล่านี้หรือทำให้สุขภาพสัตว์ดีขึ้นแล้ว

[แผนวัดผล](impact-and-sustainability.md) กำหนดนิยาม baseline เป้าหมายและวิธีเก็บ [User validation](user-validation.md) เป็น protocol พร้อม CSV template และ [บทจำลอง](interview-rehearsal.md) ใช้ซ้อมคำถามเท่านั้น ผลจริงต้องระบุวันที่ วิธีเก็บ sample และข้อจำกัดก่อนเพิ่มเข้ารายงาน

## 5. Team & Network

รายชื่อได้รับจากผู้ใช้ หน้าที่กำหนดสำหรับการทบทวน ส่งมอบ และนำเสนอ:

| สมาชิก | ส่วนรับผิดชอบ |
|---|---|
| ฐิติภัทร ไร่พันพ่าย | Frontend และ UX/UI |
| ภาษณฑ์ ศิวธนเณศ | Backend และ Database |
| วศิน จันทร์ก้อน | QA และ User Research |
| ชวเลิศ สาวิตรตระกูล | DevOps และ AI Integration |

ใช้ Codex ช่วยวิเคราะห์ พัฒนา ตรวจและจัดเอกสาร Git snapshot ใช้ยืนยันเวอร์ชัน ไม่ใช้แทนหลักฐานว่าแต่ละคนเขียนส่วนใด สมาชิกต้องทบทวนและอธิบายส่วนของตนก่อนนำเสนอ ดู [หน้าที่และ AI disclosure](team-and-ai-disclosure.md) และ [คู่มือทบทวน/คำถามตอบ](team-review-and-qa.md) ยังไม่มีพันธมิตรผู้เชี่ยวชาญที่ยืนยันแล้ว

## 6. Sustainability & Unfair Advantage

มีงบสองสถานการณ์พร้อมสูตร แหล่งราคา และ sensitivity ใน [ต้นทุน/แผนดำเนินงาน](impact-and-sustainability.md) ใช้การสนับสนุน pilot เป็นข้อเสนอ และทดสอบความเต็มใจจ่ายในอนาคต ไม่มีรายได้จริงหรือ billing feature ที่อ้างว่าทำแล้ว

จุดต่างของรุ่นนี้คือ shared care, audit/Undo และข้อมูล wellness ที่เปิดต้นทางได้ ข้อได้เปรียบที่รักษายากต้องพัฒนาจาก domain knowledge, usability validation และเครือข่ายที่เกิดจริงต่อไป ไม่อ้างว่ามี moat หรือ dataset เชิงพาณิชย์แล้ว

## 7. Demo, DevTools & System Design

ระบบใช้ Next.js/React → API/services → PostgreSQL มี Docker Compose, Jenkins, registry ภายใน Course และ health/API smoke การตรวจ runtime ที่แนบใช้ `tuchsanai/devtools:2569_1` และฐานข้อมูลทดสอบสะอาด

ผล baseline ที่ยืนยัน: Jenkins #8 SUCCESS, audit ไม่พบช่องโหว่ที่รู้จักใน production dependencies ณ รอบตรวจ, unit/API 76/76, E2E 14 ผ่าน/4 ข้ามตามแพลตฟอร์ม, publish/pull/deploy/health และ recovery ผ่าน Live-provider synthetic Chat 5/5 และ Draft 3/3 ผ่านเฉพาะกรณีที่เลือก ส่วน rollback/roll-forward ยืนยันว่าบันทึกเดโม 17 วันยังอยู่

ผล release ที่จัดส่งล่าสุดให้ยึด `evidence/release-verification.json` ที่หน้าชุดส่ง ซึ่งระบุ source revision และ build จริง เอกสาร baseline ใน Git อาจอ้าง build ก่อนหน้าเมื่อการเปลี่ยนล่าสุดมีเฉพาะเอกสาร

### เส้นเรื่องสาธิต

ผู้ดูแลสองคน → สร้างงาน → ยืนยันเสร็จ → ตรวจ Timeline → Undo → เปิด Alert/source → กำหนด follow-up → ดาวน์โหลด PDF จากนั้นแสดง permission/conflict/cancel และ Jenkins failure ที่บล็อก publish/deploy ดู [Demo script](demo-script.md)

### ข้อจำกัดที่เปิดเผย

ยังไม่มี field validation ของ PawRoutine, load/SLA measurement หรือ clinical validation ของ AI ผล PDF เป็น raster และอาจมีช่องว่างระหว่าง section การคืน image ไม่ได้ย้อน schema อัตโนมัติ รายละเอียดอยู่ใน [Known limitations](known-limitations.md)

## ข้อสรุปที่ใช้ในการนำเสนอ

ระบบพิสูจน์ workflow ด้านข้อมูลและการส่งมอบซ้ำใน Course ได้ ข้อเสนอด้านผลกระทบและธุรกิจมีวิธีวัด/งบประมาณที่ตรวจสูตรได้ ผลผู้ใช้จริงและความเข้าใจของสมาชิกต้องยืนยันด้วยการเก็บข้อมูลและการนำเสนอจริง
