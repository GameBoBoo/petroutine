# ผลกระทบ ต้นทุน และการดำเนินงานต่อ

## ผลลัพธ์ที่ต้องการและวิธีตรวจ

ผู้รับประโยชน์หลักคือผู้ดูแลสัตว์ร่วมบ้าน ผู้รับรายงานใช้ข้อมูลประกอบการคุยกับสัตวแพทย์ ระบบไม่ได้ให้สัตวแพทย์เข้าถึงบ้านอัตโนมัติ เป้าหมายคือประสานงานง่ายขึ้น ไม่อ้างผลรักษาหรือผลสุขภาพที่ยังไม่ได้วัด

ข้อเสนอ pilot: 10 ครัวเรือน ใช้วิธีเดิม 7 วัน แล้วใช้ PawRoutine 7 วัน ยังไม่มีผู้เข้าร่วมยืนยันหรือผลทดลองจริง เป้าหมายด้านล่างเป็นเกณฑ์ตัดสินที่เสนอ ไม่ใช่ผลที่ทำได้แล้ว

| ตัวชี้วัด | นิยาม/วิธีวัด | เป้าหมายที่เสนอ |
|---|---|---|
| อัตรางานที่พลาด | งานที่ผู้ดูแลยืนยันว่าไม่ได้ทำ ÷ งานถึงกำหนดที่ตรวจสอบได้ เปรียบเทียบในบ้านเดิม | ลดลง 20% แบบ relative จาก baseline; ถ้า baseline เป็นศูนย์ไม่คำนวณอัตราลด |
| ทำงานสำเร็จด้วยตนเอง | งานสร้างกิจวัตร/ยืนยัน/Undo/หาประวัติที่ทำสำเร็จโดยไม่ช่วย ÷ งานที่มอบหมาย | อย่างน้อย 80% |
| เวลาหาประวัติ | median วินาทีจนตอบถูกว่าใครทำงานแล้ว ใช้งานทดสอบเทียบกันได้ | ลดลง 30% จาก baseline |
| ความเข้าใจ Alert | อธิบายกลับได้ว่าไม่ใช่คำวินิจฉัยและควรตรวจ source ÷ ผู้เข้าร่วมที่ตอบ | อย่างน้อย 80%; ถ้าผิดต้องแก้ข้อความ |
| งานซ้ำโดยไม่ตั้งใจ | จำนวนเหตุการณ์ที่ผู้ดูแลยืนยันจาก diary | รายงานก่อน/หลังโดยไม่ตั้งผลสำเร็จล่วงหน้า |

Baseline ทุกตัว **ยังไม่วัด** อย่านับ overdue ทุกงานเป็นการลืม ต้องบันทึกการเลื่อน/ยกเลิกและ missing data รายงานจำนวนบ้าน ตัวหาร และการถอนตัว วิเคราะห์แบบ paired พร้อมข้อจำกัด self-report, learning effect และกลุ่มตัวอย่างเล็ก จำนวนบันทึกเป็น output ไม่ใช่หลักฐานสุขภาพดีขึ้น

## งบประมาณที่ตรวจสูตรซ้ำได้

ข้อมูลราคาอ้างอิงตรวจวันที่ 28 ตุลาคม 2026: [DigitalOcean Basic Droplet](https://www.digitalocean.com/pricing/droplets) 4 GiB RAM / 2 vCPU / 80 GiB SSD ราคา 24 USD/เดือน และ [weekly VM backup](https://docs.digitalocean.com/products/backups/details/pricing/) เพิ่ม 20% จึงเป็น 28.80 USD/เดือน ราคาเป็นรายการอ้างอิงเพื่อวางแผน ยังไม่ได้ซื้อหรือทดสอบ deploy/load บน cloud เครื่องนี้

สมมติฐานที่ทีมต้องทบทวนก่อนจ่ายจริง: 35 บาท/USD เป็นอัตราวางแผน ไม่ใช่อัตราตลาด; เครื่องเดิมเฉลี่ย 80 W × 6 ชม. × 22 วัน × 5 บาท/kWh = 52.80 บาท/เดือน โดย 5 บาทเป็นสมมติฐานค่าไฟ; สำรองพื้นที่เก็บ SQL dump นอกเครื่อง 30 บาท; จัดสรร AI 300 บาท ไม่ใช่ใบเสนอราคาของ provider หรือ hard cap ที่ระบบบังคับอัตโนมัติ; ดูแลรวมทั้งทีม 8 ชม. × 150 บาท = 1,200 บาท; เผื่อเงินสด 10%

ทั้งสองทางเลือกยังใช้ Course/Jenkins บนเครื่องเดิม Cloud ย้ายเฉพาะ app/DB จึงยังรวมค่าไฟเครื่องเดิม ไม่รวมซื้อ/เสื่อมราคาเครื่อง ภาษี ส่วนต่างแลกเงิน ค่ารับชำระ domain งาน TLS และบริการ 24/7 ค่า VM backup ไม่แทน SQL dump ที่ตรวจ restore ได้

| ทางเลือกสำหรับ 10 บ้าน | เงินสด/เดือน รวมเผื่อ 10% | รวมมูลค่าแรงทีม | เงินสด/บ้าน |
|---|---:|---:|---:|
| เครื่องเดิม + งบ AI | 421.08 บาท | 1,621.08 บาท | 42.11 บาท |
| Cloud app/DB + local CI + งบ AI | 1,529.88 บาท | 2,729.88 บาท | 152.99 บาท |

ปิด AI: เงินสดเครื่องเดิมเหลือ 91.08 บาท/เดือน และ cloud เหลือ 1,199.88 บาท/เดือน งานดูแลหลักยังทำงานได้ สมมติราคาทดลอง 49 บาท/บ้าน/เดือน (ยังไม่มี billing หรือลูกค้าจ่ายเงินจริง) จะคุ้มเงินสดที่ 9/32 บ้าน และคุ้มรวมมูลค่าแรงที่ 34/56 บ้าน ตามลำดับ ที่ 10 บ้านรายรับสมมติ 490 บาทจึงไม่ครอบคลุม cloud หรือมูลค่าแรงเต็มจำนวน

ข้อเสนองบ pilot เครื่องเดิม 500 บาท/เดือน หรือ cloud 1,600 บาท/เดือน ต้องยืนยันผู้จ่ายก่อนเริ่ม ยังไม่มีผู้สนับสนุนหรือ partnership ที่ตกลงแล้ว ตรวจสูตรด้วย `node docs/delivery/budget-calc.mjs` และดู [สมมติฐาน](budget-assumptions.json) / [ผลคำนวณ](budget-estimate.json) หากแก้สมมติฐานใช้ `--write` เพื่อสร้างผลใหม่

## ทีมและความต่อเนื่อง

| ผู้รับผิดชอบที่เสนอ | งานดูแล/รอบตรวจ |
|---|---|
| ฐิติภัทร ไร่พันพ่าย | UX/ข้อความ Alert และปัญหาการใช้งาน ตรวจหลังทุก pilot session |
| ภาษณฑ์ ศิวธนเณศ | สิทธิ์และ migration ตรวจทุก release; ทบทวน SQL backup/restore ร่วม DevOps |
| วศิน จันทร์ก้อน | เก็บ consent/diary วัด outcome และ regression ก่อน release |
| ชวเลิศ สาวิตรตระกูล | CI/deploy, usage/งบรายสัปดาห์, สำรองและซ้อม restore รายเดือน |

เป็นแผนรับผิดชอบ ไม่ใช่หลักฐานว่าสมาชิกทำกิจกรรมเหล่านี้แล้ว เดือนแรก: สัปดาห์ 1 สมาชิกทบทวนโค้ดและรับบทบาท/ตรวจ consent; สัปดาห์ 2 เก็บ baseline; สัปดาห์ 3 ทดลอง; สัปดาห์ 4 วิเคราะห์/ถามความยินดีจ่าย/ปรับงบ แล้วตัดสินใจดำเนินต่อหรือพัก pilot ตามผลจริง

## จุดต่างและความเสี่ยง

Shared care, audit/Undo และประวัติที่ย้อน source ได้เป็นความสามารถที่สาธิตได้ ยังไม่ใช่ unfair advantage ที่พิสูจน์ว่าคู่แข่งเลียนแบบยาก ความสัมพันธ์คลินิกและความรู้จาก pilot เป็นโอกาสในอนาคต ยังไม่ใช่ทรัพย์สินหรือข้อตกลงที่มีอยู่

| ความเสี่ยง | วิธีรับมือ/เกณฑ์ทบทวน |
|---|---|
| เข้าใจ Alert เป็นคำวินิจฉัย | disclaimer/source + teach-back; ถ้าเข้าใจผิดแก้ UX ก่อนขยาย pilot |
| ข้อมูลไม่ครบ/กดผิด | missing-data state, confirmation, edit/audit/Undo; ตรวจ diary ประกอบ |
| ข้อมูลบ้านรั่ว | ตรวจ authorization/consent และจำกัดผู้รับรายงาน; ไม่อ้างผ่าน penetration test |
| AI ตอบผิด/ช้า/ค่าใช้จ่ายเพิ่ม | ตรวจ source, timeout, ติดตาม usage และปิด AI ได้; เปลี่ยน provider ต้องทดสอบใหม่ |
| เครื่อง/ฐานข้อมูลเสีย | backup นอกเครื่องและซ้อม restore; volume อย่างเดียวไม่ใช่ backup |
| งบ/เวลาไม่พอ | เริ่ม local pilot ที่จำกัดบ้าน ทบทวนภาระ support และผู้จ่ายก่อนขยาย |
